# トマト選果 PoC 計画（2026-09-13）

## 目的
**フィジカルAIの社会実装のPoC** ＝ トマトを熟度で自動選果する機械を、自分の手で作って動かす。
（相手＝実在のトマト農家の手作業選果。将来は他産業のビンピッキングへ横展開も視野）

## 全体像：機械は「2人の担当」でできてる
- **判定係（VLM）**：トマトを見て「これは完熟／グリーンヘッド…」と**判断する**。事前学習済み＝訓練不要。位置は関係ない。汎化する。
- **手係（アーム＝SO-101）**：判断に従って**掴んで箱へ入れる**。位置が重要。ブドウのACTで実績あり。

→ この2つを別々に作り、別々に確かめ、最後に繋ぐ。

## 確定した設計判断（なぜそうするか）
1. **判定はVLM、掴みはアーム（分離型）** … 判定係は汎化・変更自在（プロンプト1行）・訓練不要。エンドツーエンドACTだと設定に固着＆微妙な熟度に弱い。
2. **当面は視覚4分類**（未熟／グリーンヘッド／色づき／表面欠陥）… 色で分かる軸はVLMが得意（実測で色100%）。
   - **物理の箱は3つ（2026-09-13確定）**: ①色づき(出荷) ②グリーンヘッド ③不良品。VLMの判定は4ラベルのまま、**ルール表で「未熟→③」「表面欠陥→③」に変換**（判定精度を保ちつつ箱を減らす。変更は1行）。
   - 根拠(ユーザーのドメイン知識): **収穫後の真緑はもう追熟しない＝売り物にならない＝正真正銘の不良品**。シワ・傷みと同じ廃棄箱でよい。熟しすぎは視覚で分けられない(実測0/3)ので色づきに含める。
3. **硬さの軸は当面やらない**（熟しすぎ・柔らか不良品）… RGB画素に写らない＝触覚が要る。SO-101は力覚なし。→将来フェーズ。
4. **山盛りとは戦わない** … まず「整列（1層＋離す＋位置固定）」してから。深い山のビンピッキングは将来。
5. **VLA／深度カメラ／横展開は将来フェーズ** … まず分離型PoCを動かすのが先。

## 過去の現在地
**Phase 1 ✅合格（2026-09-13）→ 次は Phase 2（手係）**。
- Phase 1 実測: 分離配置14個で **14/14=100%**（シワ2・未熟1のNG検出も全正解）
- **重要な追加知見**: 密集配置（皿に山盛り）だと**個体の切り分け(localization)で壊れる**ことを実測（同一トマトの緑部と赤部を別個体と誤認、隙間をトマトと誤認）。VLMは「1個の分類」は完璧だが「ピクセル位置の特定」は苦手。→ **必須なのは「1層＋離す」の分離配置のみ**（段ボール上バラ置きでOK。くぼみトレーはACT学習を省きたい場合の代替案に格下げ）
- **位置対応問題の解法＝「掴んでから判定」**: ①ACTがバラ置きから1個掴む(ブドウ方式) ②ホームへ持ち上げ ③カメラが「いま持ってる1個」を見てVLM判定（1個ならVLMは完璧、と実証済み） ④判定に応じた箱へ再生。→ 判定を掴んだ後にやることで、シーン内のどれがどれ問題・掴んだ個体との対応付け問題が両方消える
- Phase 2 でやること: 段ボールに分離配置→「掴んで持ち上げる」デモ収集→ACT学習→ホーム姿勢保存→箱への動作3本記録→単体成功率測定

## 各テスト共通の作法（毎回これを守る）
- **★開始前カメラ確認（2026-09-15制定・必須）**: データ収集/評価/統合実行の前に、必ずカメラの現在映像を撮影して提示し、ユーザーの「この画角でOK」を得てから始める。確認観点=①作業対象が写っているか ②その工程で見る必要があるもの（掴み中のアーム・判定時の持ち上げ位置等）が全部画角内か ③明るさ。Claudeが自発的に実行する。
- **測る前に合格ラインを決める**（後出しで基準を動かさない）
- **正解（ground truth）は自分が目＋触りで付ける**（VLMやアームの答えと照合する“答案”）
- **1回に1つだけ変える**（複数同時に変えると原因が分からない）
- **n≥10で判断**（少数はノイズ）
- **本番で人はラベルを言わない**。人が正解を言うのは「テストの採点」のときだけ。本番は全自動。

## 具体手順：いつ遠隔操作(テレオペ)するか
**大原則: 遠隔操作は「教材づくり」のときだけ。テストでは一切しない（ロボが独りでやるのを見て数える）。**

| ステップ | やること | 遠隔操作 |
|---|---|---|
| 1 判定係テスト | 写真→VLM分類→自分の正解と照合（色≥90%で合格） | なし（ロボ不要） |
| 2 教材づくり | (2a)「掴んで持ち上げる」デモ30〜50回→Colabで学習（位置を毎回変える・色は不問・箱に入れない）／(2b)「持ち上げ姿勢→各箱へ落とす」を各1回記録（計4本・学習なし・`lerobot-replay`で再生する用） | **ここだけ** |
| 3 手係テスト | ロボが独りで掴む→置く。見て数える（n≥10、≥80%で合格） | なし |
| 4 統合テスト | 正解既知のトマト10個→スタート→ロボが 掴む→VLM判定→ルールで箱決め→箱へ を全自動。見て「正しい箱に入ったか」を数える | なし |

- 「記録の再生」=動画ではなく**関節角度の数列**（毎秒30回×6関節）をモーターに流し直すこと。`lerobot-record`が保存しているのはまさにこれで、ACT=数列を大量に集めて一般化を学習、再生=1本をそのまま流す。箱は固定位置なので再生で足りる。掴みは位置が毎回違うのでACTが必要。
- トマトは掴むたび傷む→リセット(戻す)回数は控えめに、傷んだら交換。配置は毎回変えてよい(VLMは位置不問、ACTは位置対応を学習済み)。

## 設計教訓（2026-09-15 統合テストで判明）
- **カメラ画角は「全工程の視覚要求」で設計する**（ユーザー指摘）。今回は掴み(ACT)の画角しか考えず、判定時の「持ち上げたトマト」が画角外だった→VLMが「掴んでない」と誤判定し、その場で放す事故に。v1の対処=判定ポーズ(inspect)にトマトを持ってきて見せる。**カメラを今動かすのは不可**（学習済みACTが壊れ、デモ26本録り直しになるため）。
- **次期構成: カメラの役割分担**=作業カメラ(俯瞰・ACT用)＋**検査カメラ(近接・判定専用)の2台構成**（本物の選果機と同じ検査ステーション方式。判定画質も向上）。
- ACT実行は**学習時と同じ30fpsに厳密調速**が必須（速すぎると学習した動きの数倍速で暴走=「バーン」）。
- 手首(wrist_roll,m5)は再組立て箇所で過負荷が頻発。連投を避け、次回メンテでネジ/ギア噛み合わせ点検。グリッパの過負荷は「握りしめ保持」による正常な保護動作。
