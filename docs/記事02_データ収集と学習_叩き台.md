# SO-101にpick&placeを教える：データ収集〜学習開始まで（2026-09-01）

前回の組み立て・キャリブレーションに続き、今回はいよいよ模倣学習（Imitation Learning）でSO-101に実際のタスクを覚えさせる回。目標はシンプルなpick&place：黒い電工テープの巻きを掴んで、白い容器に入れる。

## やったこと

1. デモデータの収集（`lerobot-record`）
2. 集めたデータでの学習（ACTポリシー）
3. Mac(MPS)からGoogle Colab(GPU)への切り替え

結果として、今日中に50エピソードのデータ収集を完了し、Colab上で本番学習（100,000ステップ）を仕込んで一晩回す、というところまで到達した。

## つまずいたところ

きれいに進んだわけではなく、序盤で2つハマった。

### 1. キーボードのフォーカスが外れて、失敗デモがそのまま保存される

`lerobot-record`は録画中、右矢印＝OK、左矢印＝やり直し、で操作する。ところがmacOSのアクセシビリティ権限まわりの制約で、**録画中のターミナルウィンドウをクリックしてアクティブにしていないと矢印キーが効かない**という罠があった。気づかずに別の作業をしていたら、失敗デモがそのまま60秒経過で自動保存されてしまい、該当データセットは丸ごと削除してやり直した。

教訓：録画中は他のウィンドウを一切触らない。

### 2. カメラのフレーミングが「完了済み」の記録と実際で食い違っていた

事前の計画メモには「アーム・容器・対象物がフレームの6〜7割を占める距離感で設置完了」と書いてあったが、実際に撮れた画像を確認すると、アームや容器は画面の隅に小さく写るだけで、大半が何もない床と壁だった。ドキュメント上は「完了」でも、実物を撮って確認するまでは信用できない、という当たり前だが見落としがちなポイント。

カメラを寄せて再調整し、アーム・容器・テープが画面のバランス良く収まる位置を確認してから、本番のデータ収集に入った。

## データ収集：50エピソード完走

上記の教訓を踏まえて再挑戦。今度はモーターとの通信エラー（ケーブルの緩み）にも遭遇したが、コネクタを挿し直して解決。最終的に**50エピソード、合計36,307フレーム**を問題なく収集できた。

品質チェックとして、最初・中盤・終盤のエピソードから画像を抜き出して確認したところ、いずれも「テープを掴んで容器に入れる」という目的の動作がきちんと成功していた。

対象物（テープ）の開始位置は毎エピソード10cm四方くらいランダムにズラし、容器・アーム土台・カメラ位置は固定した。容器の位置は、置き直すたびにズレないよう、**容器の真下（置けば完全に隠れる範囲）にテープでマーキング**して目印にしている。テーブルの上に見える形でマーキングすると、それが毎回カメラに映り込んでしまい、学習データと評価データの見た目が食い違う原因になるため、あえて「置けば隠れる」位置を選んだ。

## 学習：Mac(MPS)からColab(GPU)へ

ACTポリシー（ResNet18バックボーン、約5,200万パラメータ）で学習。まずMac(MPS)で10ステップ→3,000ステップのスモークテストを実施し、lossが順調に下がることを確認（15.0 → 0.8）。

ただし本番の100,000ステップをMacで回すと**13〜14時間**かかる計算になったため、Google Colab（GPU、Pro）に切り替えることにした。ローカルのデータセットをzipにしてGoogleドライブ経由でColabに渡し、同じ`lerobot-train`コマンドを`--policy.device=cuda`で実行。

Colab側でも`av`パッケージ不足のエラーが出るなど細かい躓きはあったが、`pip install "lerobot[dataset,training]==0.6.0"`で解決。GPU（T4クラス）では約3.4 step/秒と、Macの約1.6倍の速度で学習が進み、8時間強で完走する見込み。

途中で「Colabが夜間に切断されたら学習が消えるのでは」という懸念も出たが、対策として`output_dir`を最初からGoogleドライブ直下に向け、5,000ステップごとのチェックポイントが自動でドライブに残る設定に変更した。

## 現在の状態

- データ収集：✅ 完了（50エピソード）
- 学習：✅ Colab(GPU)で100,000ステップ完走
- 評価：✅ 実施（下記）

## 評価結果

翌朝、Colab側の学習が無事100,000ステップ完走していることを確認。チェックポイントをGoogleドライブ経由でダウンロードし、Mac上で評価を実施した。

評価には新設された`lerobot-rollout`コマンド（`--strategy.type=episodic`）を使用。リーダーアームは不要で、フォロワーアームと学習済みポリシーだけで自律的にpick&placeを実行させ、成功/失敗を目視で記録する形。

**結果：10試行中9回成功（成功率90%）**

唯一の失敗は「掴み損ね」（テープの巻きを掴もうとしてグリップが空振り、掴めなかったパターン）。それ以外の落下・位置ズレ等の失敗は見られなかった。

50エピソードという比較的小さいデータセットでも、単一物体・単一容器・固定カメラという条件が揃っていれば、初回学習でここまでの成功率が出ることが確認できた。

## 次回予告

失敗モード（掴み損ね）が今後もう少しサンプルを増やせば傾向として見えてくるかもしれない。次はカメラを手首にも追加する、あるいは容器や照明条件を変えて汎化性能を試す、といった発展を検討中。
