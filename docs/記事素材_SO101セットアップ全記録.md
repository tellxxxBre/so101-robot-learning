## 0. 機材構成
- **キット**：Seeed Studio SO-101 オープンソースロボットアームキット **Pro版**（秋月電子・販売コード131228）

- **PC**：Mac（Apple Silicon）、lerobot 0.6.0（`~/practice/so101-blog/.venv`）

## 1. 時系列（ハマった順）

### Phase 1：物理配線の地獄（ソフト屋が一番詰まる所）
- **充電専用ケーブルの罠**：USB-Cケーブルには「充電専用」と「データ通信対応」があり、充電専用だとMacが基板を認識しない（ポートが出ない）。見た目で区別不能
- **電源端子**：基板の電源は**緑のネジ端子（DC 5-12V, +/−極性表記あり）**。丸いDCジャックじゃなく、DCジャック付ケーブルの2本線をネジ留め。赤=＋/黒=−
- **⚠️電圧**：**Follower=12V / Leader=5V**。Leaderは7.4Vモーターなので12Vを挿すと過電圧で焼損（公式に "otherwise you might burn your motors!" と警告）。基板は電圧をそのままモーターに流す＝人間が正しいアダプターを選ぶ責任
- **USB接続**：基板USB-C ↔ Mac。MacがUSB-Cのみ→**USB-A→C変換アダプタ**か**USBハブ**経由。ポートハブ(UGREEN CM219)経由でも認識はできた
- **USB認識確認**：`ls /dev/cu.usbmodem*` でポート出現＝認識成功。`system_profiler SPUSBDataType`でUSB機器0だったのが、ケーブル差し直しで `/dev/cu.usbmodem5B7B0090111` 出現

### Phase 2：核心の謎「モーターが1個も応答しない」
- 症状：ポート認識OK・基板LED点灯・でも `lerobot bus.ping` で**全ID(1-6)・全ボーレート(1M/500k/…)応答なし（すべてNone）**。関節はスカスカ（保持トルクなし）
- **潰した容疑者（全部シロ）**：
  - 電源：USB抜いてもLED点灯＝12Vは基板に来てる ✓
  - USB：Macがポート認識＋lerobotで開ける＋ping送信は成功 ✓
  - ジャンパ：Pro版はUSBモード設定済み。可動ジャンパ着脱でも変化なし ✓
  - USBハブ：USB-A→C変換で**直結しても同じ**＝ハブは無関係 ✓
  - 電圧：Followerは12Vモーターに12V＝正しい（過電圧でない） ✓
- → **「基板のサーボ駆動部の初期不良」と結論しかけ、秋月への返品文面まで準備**

### Phase 3：逆転（真犯人＝ID衝突）★記事の山場
- きっかけ：ユーザーの一言「**モーターの設定を間違えたケースは?**」→ ID未設定を再考
- **仕組み**：STS3215は工場出荷時**全部ID=1**。数珠つなぎのまま「ID=1いる?」と聞くと、**6個が同時に返事→信号がバス上で衝突→壊れたデータ→PCは"無応答(None)"と誤認**。ID 2-6は誰もいないので当然無応答。→ **全部Noneでもモーターは生きてる**
- **決定的な診断＝生バイト観測**（`raw_probe.py`）：
  - フルチェーン時：1Mbaudで `ff4020fc`（**壊れたバイト**が返る）＝衝突＝モーター生存の証拠。他baudは0バイト
  - 孤立後：`ffff010200fc`（=ヘッダFFFF, ID=1, error byte=**00＝アラームなし健康**, チェックサムFC）＝**完璧なクリーン応答**
  - **教訓**：`bus.ping`のNoneは「壊れて返ってる(衝突=生きてる)」か「沈黙(0バイト=故障)」かを区別できない。**生バイトを見れば切り分く**

### Phase 4：修復（ID焼き）
- **組立後はコネクタが3Dプリント関節に埋没**→ラジオペンチが入らない→**精密マイナスドライバーで隙間にテコを入れて浮かせる**（掴むより狭所向き）
- **1個ずつ孤立**（基板線を対象モーターに挿し替え＋下流の3ピン線をテコで抜く）→ `set_id.py` でID書込み → 2,3,4,5,6を順に焼く
- ID書込みの中身：**LOCKレジスタ(addr55)=0で解錠 → IDレジスタ(addr5)=新ID → LOCK=1で施錠**（baud=1,000,000）。lerobotのpacket_handlerで `write1ByteTxRx`
- 全部を数珠つなぎに戻す→**6個(ID1-6)が衝突なく応答**（全部modelナンバー777=STS3215）
- **★最大の教訓**：**ID設定は"組み立て前"に1個ずつやるべき**。公式手順もその順だが強調が弱く、多くのガイドは「いきなり組み立て」。失敗時のエラーが「モーター認識されない」とズレてて全員がケーブル/電源を疑う。組立後は上記の地獄

### Phase 5：キャリブレーション（Follower）
- コマンド：`lerobot-calibrate --robot.type=so101_follower --robot.port=/dev/cu.usbmodem5B7B0090111 --robot.id=my_follower`
- 流れ：全関節を中央にしてEnter → 各関節を可動域の端から端まで動かす（MIN/MAXが記録される）→ Enter → 自動保存
- **ハマり**：途中で `ConnectionError: ... There is no status packet!` で落ちた。静止時は6個応答するのに動かすと落ちる＝**再接続した3ピンの半挿し（動かすと接触が切れる）**。全コネクタを"もう一段"押し込み＋ケーブルにたるみを持たせて再実行→完走
- 記録値の実測（参考）：shoulder_pan 779-3571 / shoulder_lift 1057-3568 / elbow_flex 341-2521 / wrist_flex 278-2690 / gripper 1967-3482。wrist_roll(ID5)は別処理で除外＝正常
- 保存先：`~/.cache/huggingface/lerobot/calibration/robots/so_follower/my_follower.json`

### Phase 6：Leaderアーム
- 手順はFollowerと同一（孤立→焼く→較正）。★**電源は5V**（7.4Vモーター、12V厳禁）
- Leaderのポート：`/dev/cu.usbmodem5B7B0094901`（Followerの…0111とは別）。基板は2枚目（テレオペで両アーム同時接続するため1本1枚）
- Leader基板の書込みも往復テスト(1→2→1)で確認済み。**M1〜M6を順にID 1-6へ焼き完了**（Followerの経験で爆速）
- 数珠つなぎに戻して **6個(ID1-6)が衝突なく応答** を確認済み
- 較正コマンド：`lerobot-calibrate --teleop.type=so101_leader --teleop.port=/dev/cu.usbmodem5B7B0094901 --teleop.id=my_leader`（Followerは--robot.type、Leaderは--teleop.type）
- **Leader較正完了**。★ハマり：1回目の較正で gripper が 2044-2047(幅3=未記録)、shoulder_pan/lift が 0-4095(偽の全域=エンコーダ境目またぎ)になった。原因＝**リーダーのgripperは"トリガー(引き金)"を握って動かす**必要があるのに握ってなかった＋肩を境目またいで回した。`c`で再較正し、トリガーを全開全閉＋肩を自然域で振り直して良好値に（gripper 2025-3327 等）。保存先 `~/.cache/huggingface/lerobot/calibration/teleoperators/so_leader/my_leader.json`
- ★較正の2段階：①「middleにしてEnter」段階は**数字が出ない**（真ん中にしてEnter）→②「Recording」段階で**表が出て動かすと数字が変わる**。既存ファイルがあると `Press ENTER to use ... or type 'c'` と聞かれる→**`c`+Enterで再較正**

### Phase 7：テレオペレーション ✅ 成功（2026-08-13）
- 両アームを**同時にMac接続**（Follower 12V/port…0111、Leader 5V/port…94901）。USB2本要る→**UGREENハブ(CM219)に2枚挿し**で解決（キット付属A-Cケーブル×2）。※ハブは元々シロだったので問題なし
- コマンド：`lerobot-teleoperate --robot.type=so101_follower --robot.port=<follower> --robot.id=my_follower --teleop.type=so101_leader --teleop.port=<leader> --teleop.id=my_leader`
- **Leaderを手で動かすとFollowerが追従＝成功**。テレオペで追従した＝両アームの較正(基準含む)が正しかった証明
- ★注意：起動時にFollowerがLeaderの姿勢へ動くので、**両アームを似た姿勢にして・Follower周りを片付けてから**起動（急な大振り防止）。use_degrees=True, fps60, max_relative_target=None
- ★較正の「middle(真ん中)」段階の意味：リーダー/フォロワーが「どこが中央か」を共通認識する基準。②のMIN/MAX(可動域)とは別。テレオペが正常追従すれば基準もOK

## 2. 記事の"差別化"ポイント（日本語で正確な記事がほぼ無い所）
1. **「モーター認識されない」の真犯人はID未設定の衝突**。エラーメッセージがミスリードで全員が回り道
2. **生バイト診断**：「壊れて返る＝生きてる(衝突)」vs「沈黙＝故障」の見分け方
3. **ID設定は組立"前"に必須**。組立後はコネクタ埋没で地獄
4. **Follower=12V / Leader=5V**。電源電圧の取り違えでモーター焼損
5. **USBハブ・充電専用ケーブル**という初歩の罠（ソフト屋ほど盲点）

## 3. 技術リファレンス
- **ポート**：Follower `/dev/cu.usbmodem5B7B0090111` ／ Leader `/dev/cu.usbmodem5B7B0094901`
- **ID設定レジスタ（STS3215）**：LOCK=addr55（0=解錠/1=施錠）、ID=addr5。通信 baud=1,000,000（工場デフォルト）
- **正常応答パケット**：`FF FF <ID> 02 <error> <checksum>`（例 `ffff010200fc` = ID1・error0）。model番号 **777 = STS3215**
- **自作スクリプト**（scratchpad、`SO_PORT`環境変数でポート切替）：
  - `raw_probe.py`：生バイトで衝突/沈黙を判定
  - `scan5.py`：lerobot `bus.ping` で ID1-6 を順次確認
  - `set_id.py <new_id> [cur_id=1]`：孤立した1個のIDを焼く
- **主要コマンド**：
  - 較正(Follower)：`lerobot-calibrate --robot.type=so101_follower --robot.port=<port> --robot.id=<name>`
  - 較正(Leader)：`lerobot-calibrate --teleop.type=so101_leader --teleop.port=<port> --teleop.id=<name>`
  - テレオペ：`lerobot-teleoperate ...`（両アーム完成後）
