# SO-101 Robot Learning

SO-ARM101（オープンソースの小型ロボットアーム）を個人で組み立て、果物の選果・分類タスクを題材に、**模倣学習（ACT）と VLA（SmolVLA）を実機で**試した個人プロジェクトの記録です。データ収集 → 学習 → 評価 → 実機デバッグまでを一人で一周しました。

> 自主プロジェクト。学習データセットとモデル重みは容量の都合で本リポジトリには含めていません（コード・設定・開発記録のみ）。

## ハイライト

- **SO-ARM101（Follower + Leader）を自分で組み立て・配線・キャリブレーション**。手首カメラの後付け、2カメラ同時ストリーム（約29fps）まで対応。
- **模倣学習（ACT）**
  - ブドウの色別分類：約100エピソードで安定（成功率 約90%）
  - ミニトマトの選果、テープの pick & place
- **VLA（SmolVLA 450M / LoRA）— 牡蠣ぬいぐるみの言語条件付き把持**
  - 「箱に入れる / お辞儀させる / 赤い袋を箱に入れる」の3指示を1モデルで扱い、**言語で行動が切り替わるか**を測る設計（単一物体だと言語が飾りになるため、2物体 × 2動作 + distractor + 配置シャッフル）。
  - v1（60デモ / 単眼）：**0/5 失敗**。診断の結果「大まかに近づくは学べたが、精密把持と言語切り替えが未達」。各タスク20デモという薄いデータが主因と分析。
  - v2（89デモ / 2カメラ）：**指示ごとに行動が変化し始める**（box→箱 / bow→持ち上げ）。ただし把持精度は不足 → エポック数の計算から「学習不足（undershoot）」と特定し、再学習が次の一手。
- **VLM（Claude）によるトマトの出荷可否判定**：出荷可 / 腐敗 / グリーンバック（追熟）を VLM で判定し、ルールベースで仕分け。

## 実機で得た学び

- **薄いデータ領域では、end-to-end な VLA より「1タスク専任 ACT × N ＋ 外側で言語ルーティング」の分離設計のほうが確実**（文献とも整合：構造化 Pick で ACT > SmolVLA > π0.5）。
- 実機デバッグの切り分け：「ピングが通る ≠ 健康」「静止で生存 / 動くと死ぬ」等で原因を局所化。**破損の真因はサーボ不良ではなく未確認キャリブレーション**だった（ソフトの不備がハードを壊す）。
- 「品質が低い」と感じたら推測で語らず、まず診断ログ（実効 fps・推論レイテンシ）とエポック数の計算で、無料の切り分けを先に行う。

## リポジトリ構成

```
notebooks/   Colab 学習ノート（ACT: ブドウ / テープ、SmolVLA: 牡蠣 v1・v2 / ブドウ）
src/
  ├─ diag_bus.py / diag_bus_torque.py / check_plate_alignment.py   サーボ・組立の診断
  ├─ tomato_sort/   VLM(Claude) でトマト選果（ANTHROPIC_API_KEY を環境変数で使用）
  └─ oyster_vla/    牡蠣 VLA のデータ収集・評価・対話実行スクリプト
docs/        開発記録（組み立て全記録・牡蠣VLA全記録 ほか。実話・実測の一次記録）
images/      組み立て・購入時の写真
```

## 使い方（概要）

- 学習は Google Colab（A100）で `notebooks/` の各ノートを実行。データセットは別途（Hugging Face / Drive）。
- 実機操作・データ収集は [LeRobot](https://github.com/huggingface/lerobot) ベース。組み立ては `docs/01_組み立てガイド_公式準拠.md` を参照。
- トマト選果は `export ANTHROPIC_API_KEY=...` のうえ `src/tomato_sort/tomato_sort.py` を実行。
